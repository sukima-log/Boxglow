# Boxglow で Boxglow を管理してみた所見 (dogfooding)

計画の正本は `boxglow.json`。ここには、Claude Code がこの計画を使って作業したときに分かったことをまとめる。
(この文書自体が、箱「Claude Code との相性の確認」の成果物)

## 分かったこと

- Claude Code のタスク分解力そのものは、この仕組みがあっても上がらない。上がるのは次の 3 つ:
  1. 人が「今なにが計画され、何が終わり、どこで判断を待っているか」を一目で見られる (全体像の視認性)
  2. 判断を `ask` で記録してから先へ進むので、AI が勝手に決めて進める事故が減る
  3. 入出力と成果物 (ファイル・URL・コミット) を書かされるので、「何ができたのか」が後から追える
- 入出力が抽象的になりやすい (「機能一式」「所見」など)。これは AI の癖というより、完了した仕事を後から粗い粒度でまとめたときに起きる。
  対策: 出力名は具体的な成果物にする (`設計書 docs/design.md`、`PR #12`、`公開 URL`)。`done` は成果物なしだと注意が出る。
- 末端の箱は出力 1 本という制約があるため、1 つの作業で複数の物ができるときは「箱を分ける」か「親の出力を複数にして集約の子を置く」。
- 最初の 1 日で CLI の不便を 14 件見つけ、13 件をその場で直せた。計画の箱 (運用で見つかった改善) に積むことで、直し忘れが無かった。

## 運用で見つかった改善 (抜粋)

- 題名にドットがあると結線できない / 既存の箱に入出力を足せない / 線を外せない / 最上位の出力名を変えられない → CLI に port / disconnect を追加
- 開いただけで書き込み権限を求める / 保存されたか分からない → 読み取りだけで開き、Saved / Unsaved の札と Save ボタン
- 線が箱を横切る / 線どうしが重なる → 経路の罰を強化、横の線分も広げる、通る本数で列の間隔を広げる
- 複数人で 1 つの JSON を編集すると衝突 → 箱単位の 3 方向マージ (`boxglow merge` / `git-setup`)

## 2 日目に分かったこと

- 見た目の指摘は「定数を変えた」では終わらない。実測 (線と箱の距離、並走の長さ) と拡大画像で確認してから報告する。
- 大きな計画の俯瞰は、表示の細工 (文字の拡大、画面だけの畳み) より「余白の設計」と「計画の形」で決まる。1 つの箱の下に 20 個の末端が並ぶと親が縦に伸びて他の列が空く。箱を別の親へ移す `move` を足したので、次はテーマごとの中箱に整理する。
- 線の重なりの根本原因は、親の縁 (壁) の扱いの不具合だった (横の通路の空き幅が 0 になる)。余白を広げても直らないときは、計算そのものを疑う。
- 選択の表示は「少し強調」では足りない。別の色 (橙)、動き (流れる破線)、他を薄くする、つながりを全部 (親の縁を越えて) 強調する、までやって初めて分かる。
- 判断は「選んだもの」だけでなく「選ばなかった候補」と「以前の答え」を残す。方針転換のときに戻れる。

## 進め方の約束 (CLAUDE.md より)

status を読む → start → 作業 → done (成果物付き) → 判断が要れば ask。不便は箱「運用で見つかった改善」に add して、小さいものはその場で直す。
